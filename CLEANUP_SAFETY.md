# Cleanup safety

Before removing project files, check Git status and confirm whether the file is used by the application, a migration, a dataset import, or a local development environment.

## Keep these files and data

- `.env` and `backend/.env`: local configuration and secrets. Keep them out of Git and do not print their contents in logs or support notes.
- `backend/codeassessment.db` and the Docker `postgres-data` volume: local user and submission data. Back up before any database reset or migration cleanup.
- `codeassessment-problem-bank-verified-20260927.jsonl`, `complexity_analysis.json`, and `optimal_tc_mapping_tmp.csv`: problem-bank/complexity input data. The CSV is read by `backend/dataset/merge_optimal_tc_mapping.py` despite its `_tmp` suffix.
- `backend/migrations/versions/`: schema history needed to upgrade existing databases.
- `backend/venv/`: local Python environment. It can be recreated from requirements, but deleting it will disrupt the current local setup until rebuilt.
- `frontend/src/`, `backend/`, Docker files, and `docs/`: application code and project documentation.

## Safe generated cleanup

Python `__pycache__` directories and `.pyc` files outside the active virtual environment are generated bytecode and can be recreated. Keep the virtual environment and its contents unless intentionally rebuilding it.

Do not use broad recursive deletion commands on the repository, database volumes, datasets, or environment files. Review each candidate and its references first.
